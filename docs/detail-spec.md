# Texcel 詳細設計書

本書は [基本仕様書](basic-spec.md) の振る舞いを実現する構造と規則を定義する。実装手順や作業計画は扱わない。

技術の採用根拠は1節、依存ライブラリへの局所変更は11節、確認の範囲と未確認事項は12節に記す。ライブラリ選択は設計方針であり、実行検証の合格を意味しない。

## 1. 技術選定

### 1.1 結論

Rust＋egui／eframeを採用する。デスクトップ用の単一アプリケーションとし、描画はeframeのwgpuバックエンドを使用する。Rustでデータ処理とUIを統一し、グリッドの描画対象と更新タイミングを直接管理する。

これは公式情報に基づく設計判断であり、比較ベンチマークで最速を確認したという意味ではない。IME、文字配置、独自グリッドのアクセシビリティはアプリ側の責務を含む。GPUが利用できない環境では起動エラーを明示し、独自の描画フォールバックは持たない。

### 1.2 比較と採否

調査日：2026-11-14。資料が示す機能と、Texcelへの適性に関する判断を分ける。

| 候補 | 公式資料で確認できる特徴 | Texcelでの判断 |
| --- | --- | --- |
| Rust＋egui | 即時モードUI、ネイティブ実行、AccessKit連携 [1][2] | 採用。表の直接描画とRustへの統一を重視。完成済みのExcel互換グリッドとは見なさない |
| Rust＋Tauri | RustのコアとOS別WebView、プロセス間通信 [3] | 有力な代替。文章描画に適するが、今回はWebView差とUI・コア間転送を持ち込まない |
| Qt Quick | TableViewの要素再利用、選択・編集機構 [4] | 有力な代替。C++／QMLやRust連携の追加構成を採らない |
| Slint | Rust等から利用する宣言的GUI、複数のライセンス体系 [5] | 利用可能だが、独自グリッドのために別UI言語を加える利点を重視しない |
| iced | Rust UIとIME用API [6] | 利用可能だが、今回の直接描画中心の設計ではeguiを選ぶ |

eguiを選ぶことでIMEや支援技術への対応が自動的に完成するわけではない。公式のアクセシビリティ説明でも、独自描画には意味情報を付与する必要がある [2]。Windows・macOS・Linuxの対象OSと、各バックエンドで実際に利用できる支援技術を区別する。

### 1.3 主要ライブラリ

| 用途 | 選択 | 境界 |
| --- | --- | --- |
| UI・ウィンドウ | egui、eframe | ファイル形式や計算処理から分離 |
| ネイティブメニュー | muda 0.21.2 | macOS/Windowsのみ。Linuxはeguiのメニュー。操作実装は共通 |
| Markdown構文 | pulldown-cmark | GFMのテーブル・修飾検出とオフセット取得。元バイト列の保持はアプリが担当 [7][8] |
| HTML構文 | html5gum 0.8.4 | WHATWG tokenizerとsource byte span。DOM全体の再出力には使わない |
| CSV | csv、encoding_rs | レコード解釈と文字コード変換。元の引用符・区切り位置は別途保持 |
| XLSX | umya-spreadsheet | 値と書式の読み込みだけに使い、XLSXへは書き出さない。内部モデルへ変換し、未知の要素の保持を契約にしない [9] |
| ODS | zip、quick-xml | `content.xml`・`styles.xml`だけを読み、XLSXと同じシートの中間データへ変換する。ODSへは書き出さない |
| 数式 | IronCalc | 評価と参照変換を薄いラッパーから利用。元データの保存責任は持たせない [10] |
| 設定・復旧情報 | serde＋JSON | ローカルの補助情報のみ。独自文書形式にはしない |

依存バージョンはロックファイルで固定する。計算エンジンやXLSXライブラリを複数併用しない。数式のパーサー・依存グラフを別途自作しない。

calamineは値中心の読み込み用途で、書式の網羅的取り込みには適さない [11]。rust_xlsxwriterは新規ファイル作成用で既存ファイルを編集せず、数式を計算しない [12][13]。したがって、この2つを組み合わせるだけで書式付き往復編集ができる設計にはしない。ODSを読む既存のcrateもcalamineで、修飾・リンクを返さない。ODSは読むべき要素が少なく、既に依存しているzipとquick-xmlで必要な範囲を読めるため、新しい依存を加えず読み込み部を持つ。

## 2. アプリケーション構成

1つのRustパッケージを基本とし、以下をモジュールで分ける。プラグイン機構、サービス分割、汎用リポジトリ層、イベントソーシングは導入しない。

| モジュール | 責務 |
| --- | --- |
| `ui` | グリッド、編集バー、ダイアログ、選択、描画 |
| `document` | 文書・表・セル、編集コマンド、Undo／Redo |
| `formats` | Markdown・CSVの読み書き、HTML・XLSX・ODSの取込、変換レポート |
| `calc` | 数式評価、結果状態、参照更新 |
| `storage` | 安全なファイル置換、保存時の外部変更の確認、設定、復旧 |

UIスレッドが編集状態を所有する。読み込み・保存・計算・一括処理は制限付きのワーカーで実行する。メッセージには文書ID、リビジョン、ジョブIDを付ける。UIは進捗と完了通知を受け取り、古い計算結果を破棄する。利用者向け通知は意味を表すメッセージIDと型付き引数で保持し、現在のアプリ言語で表示時に解決する。外部ライブラリやOSの詳細は翻訳された主文と分けて示す。

通常のセル確定は同期的な小さな編集として反映する。一括処理中は対象文書の編集だけを一時的に止め、移動・閲覧・別文書の操作を許可する。計算中・保存中は編集可能とし、確定した版の結果だけを反映する。

## 3. データモデル

### 3.1 文書とセル

| 型 | 主な情報 |
| --- | --- |
| `Document` | ID、編集モデル形式、保存先、表一覧、現在の版、保存済み版、読み込み元情報 |
| `Table` | ID、名前、使用範囲、ヘッダー設定、行データ、列設定 |
| `Cell` | 入力内容、取込済みの計算結果、計算結果（編集中のセルは書式を持たない） |
| `CellInput` | 空、文字列、型付き値、数式のいずれか |
| `CellStyle` | Markdown文字修飾、列配置 |
| `CalcResult` | 値、状態、評価対象の版 |
| `ViewState` | 選択、スクロール、ライブ／ソース表示、列幅 |
| `SourceSnapshot` | 元バイト列、読み込み形式、表・レコード・セルの元位置 |

取込時の書式は、取込の中間データの表ごとの疎な書式表と、クリップボードの貼付データだけが持ち、編集中のセルは持たない。

空セル、空文字列、存在しないCSVフィールドを区別する。CSVの行は元のフィールド数を持ち、描画の都合で補ったセルを保存しない。CSV・Markdownの編集文書は同じ表操作とMarkdown修飾を使う。CSV由来の未変換文字列はMarkdownとして解釈せず、Markdown編集へ昇格する際は表示文字列を保つようescapeする。XLSX・ODS・HTMLの読み込み元形式は診断と表示名にだけ使い、編集モデル・保存先はMarkdownとする。新規文書もMarkdownとして作るため、編集中の文書は常にMarkdownまたはCSVの原文を持ち、原文のない文書の保存・復旧・構造変更の経路は持たない。

行はベクター、行内セルは列番号で引ける疎な格納とする。書式は共有テーブルから参照する。データベースやディスクページングは導入せず、使用可能メモリを超えるデータは理由を示して読み込みを中止する。巨大な空のXLSX範囲を全セル展開しない。

### 3.2 原文と派生情報

CSV・Markdownの原文を、描画結果から逆生成しない。入力内容が正であり、構文解析・数式結果・描画用テキストはキャッシュとする。Markdown編集文書の各セルはMarkdown記法を含む原文を持つ。CSV由来値をMarkdown編集文書へ昇格するときは、エスケープ済みMarkdownを原文にし、元CSVの値の見え方を保つ。

Markdownのセル編集用原文は、外側の区切りと余白を除いた記法である。表構造のためのパイプエスケープと `<br>` は編集用に可逆変換する。未編集セルは再生成せず元のバイト列を使う。ライブ表示の修飾データは同じセル原文から導出し、全文文書ソース編集は行わない。

リンク・コードなどの修飾操作も、保存用原文とセル編集用入力を同じ変更として確定する。再編集で変更前の原文へ戻らないよう、計算入力とUndoも同じ版へ対応させる。修飾の追加・解除では表示文字列を保ち、文字列指定markerやMarkdownのescapeをコード内の実文字へ変えない。選択境界のため安全に表現できない場合は入力を保持して理由を示す。数式の判定には編集中の入力と既存の共通規則を使い、Text型に格納されていることだけで通常文字列とみなさない。

HTML文書は読み込み専用の入力であり、元HTMLを編集モデルや保存先にしない。既存HTML parserで表を抽出してMarkdown表へ変換する。入れ子・曖昧な表や意味を変える要素は変換レポートへ示す。スクリプトとスタイルは実行・取得しない。

表示の優先順位は次のとおり。

1. 編集中は編集バッファを表示する。
2. 数式指定なら数式を評価する。結果文字列をMarkdownとして再解釈しない。
3. Markdown編集文書の通常文字列ならインライン修飾を描画する。
4. CSV由来の未変換文字列ならMarkdown記号として再解釈せず、元文字列を表示する。
5. その他は値から表示を生成する。

## 4. 編集状態とコマンド

リボンとツールバーは実装しない。メニュー、右クリックメニュー、ショートカット、数式バー右隣のモード切替は同じ操作識別子と実行可否判定を共有する。macOS/WindowsのネイティブメニューとLinuxのeguiメニューは、階層・翻訳キー・操作ID・ショートカット・チェック種別を持つ1つの静的定義を使う。OS固有のアプリメニューと最近使ったファイルだけを各adapterで足す。ショートカット表示は実際の割当てから作り、メニュー名へ文字で埋め込まない。入口ごとに編集処理を複製しない。操作不能時は無効表示と理由を示す。設定一覧には標準ウィジェットを使い、独自のカスタマイズ基盤は設けない。

操作は具体的なコマンドenumと共通の実行可否判定を持つ。メニュー、ショートカット、右クリックはコマンドを要求するだけとし、コピー・保存・構造変更等の実処理を入口ごとに作らない。入力のownerはグリッド選択、Texcelのセル編集、他の文字入力欄、モーダル、IMEを区別する。文字入力欄が所有するCopy/Paste/Undoをグリッドへ二重適用しない。入力欄の同一frameの内容更新を反映してから文書コマンドを処理する。

ダイアログ中でも、そのダイアログの文字入力欄に対する通常の切り取り・コピー・貼り付け・Undoは使える。背後のグリッドや文書コマンドを許可する理由にはしない。IME中のキー処理は引き続きIMEを優先する。

ネイティブメニューはメインスレッドで初期化し、イベントを共通コマンドへ渡して再描画を要求する。macOSでは `NSWindow` の自動タブ機能を無効にし、OSが「タブバーを表示」を追加しないようにする。有効状態・チェック・言語・選択文書が変わったときに項目を同期する。メニューのためだけの継続再描画はしない。macOSの既定メニューは無効化し、既存の終了確認を経由する。Windowsはメッセージループでアクセラレーターを処理し、処理した同じキーをeguiへ再適用しない。2つ目以降の文書ウィンドウには、メッセージフックで最初のメッセージを受けたときにメニューを付ける。mudaは閉じたウィンドウの記録を残し、WindowsはHWNDの値を再利用するため、記録が残る値の新しいウィンドウでは記録を外して付け直す。ヘルプウィンドウにはメニューを付けない。新しく開いた文書のウィンドウには前面化を要求する。エクスプローラーやFinderからドロップしたときは送り元のアプリが前面に残り、Windowsは新しいウィンドウを前面にしない。共有メニューの操作先は最後にフォーカスを持って描画したウィンドウの文書なので、前面にならないとメニューの操作が元のウィンドウへ届く。付与はアプリ状態の借用を解放してから行う。`SetMenu` がウィンドウの大きさを変え、eframeがWindowsでは同期的に再描画してアプリ処理へ再入するためである。

ヘルプの本文は `assets/help/help.{en,ja}.md` に置いて実行ファイルへ埋め込み、pulldown-cmarkで読んだブロックを `ui::markdown_view` がeguiで描く。この描画部品は文書のミニマップと共用する。ヘルプウィンドウは文書ウィンドウと別の1つのビューポートで、開いている間も各文書の操作を止めない。スクロールバーはウィンドウの端に置き、本文の余白はスクロール領域の内側に取る。表の列は収まる限り内容の幅を保ち、収まらないときは幅の広い列から折り返す。列が多すぎるときは列の間隔も縮め、1文字も入らない列ははみ出した部分を切り取る。セルは区切り行の配置に従って列の中で左・中央・右に揃える。末尾の付録は計算アダプターの `SUPPORTED_FUNCTIONS` と同じ関数を説明し、テストで一致を確かめる。winitは描画ビューを常に文字入力の受け手として扱うため、macOSはヘルプウィンドウでも入力モードを表示する。そこでwinitのビュークラスに `inputContext` を加え、ヘルプウィンドウでは入力コンテキストを返さない（他のウィンドウはNSViewの既定どおり）。

メニューの配置は次の分類に揃える。表示だけの設定をファイル内容の編集コマンドへ混ぜず、長い説明や対応関数の一覧はヘルプで示す。macOSのアプリメニューに移す項目は他のメニューへ重複して置かない。

| メニュー | 主な操作・グループ |
| --- | --- |
| Texcel（macOS） | アプリ情報、設定、サービス等のOS標準項目、終了 |
| ファイル | 新規、開く、最近使ったファイル／保存、名前を付けて保存（形式・式か計算結果か・CSVの対象表を選ぶ）、閉じる。エクスポート、取り込みレポート、外部変更の確認、CSV設定での再読み込み、復元の項目は置かない。macOS以外では設定と終了も置く |
| 編集 | Undo/Redo／切り取り、コピー、形式指定コピー、貼り付け、形式を選択して貼り付け、テキストとして貼り付け／検索、置換 |
| 表示 | 表示モードの切替（1項目。現在がライブ編集なら「ソース編集に切り替え」、ソース編集なら「ライブ編集に切り替え」と表示し、Ctrl/Cmd＋/を割り当てる）／シートの拡大・縮小・100%に戻す（サブメニューにせず直下に置く）／折り返し／列幅、固定表示などのローカル設定 |
| 挿入 | 行・列の挿入（Ctrl/Cmd＋Shift＋R／C）。削除・移動は置かない |
| 書式 | 太字（Ctrl/Cmd＋B）、斜体（Ctrl/Cmd＋I）、打ち消し（Ctrl/Cmd＋Shift＋X）、インラインコード（Ctrl/Cmd＋E）、リンク／列の左・中央・右寄せ |
| 表 | 行・列・フィルのサブメニュー（削除・複製・移動、コピー・連続データ）／表の追加・複製・削除。「表」の中に「表」のサブメニューを重ねないよう、表の操作は直下に置く |
| データ | 並べ替えを直下へ／重複・空白・分割・結合・転置などの整理／数式結果への置換。フィルターは設けない |
| ウィンドウ（macOS） | しまう（Cmd＋M）、拡大／縮小、開いているウィンドウの一覧 |
| ヘルプ | Texcelのヘルプ（内蔵の操作説明と対応関数を別ウィンドウで表示）、Texcelについて（macOS以外。macOSはアプリメニューの標準パネルに著作権表示を加える） |

通常のCopy/Pasteは固定動作とし、特殊コピーは形式を引数にした独立コマンド、特殊貼付は1回の要求に含まれるoptionsとする。optionsは「テキストのみ」「計算結果の値」「修飾を外す」「転置」「空白スキップ」の独立したフラグで、テキストとして貼り付けは「テキストのみ」だけを立てたoptionsである。メニューを閉じた後に見えないグローバルな貼付モードを残さない。eguiはCtrl/Cmd＋Vに修飾キーが加わっても同じ貼付イベントを送るため、グリッドはそのときの修飾キーでShiftならテキストとして貼り付け、Ctrl＋Alt（macOSはCmd＋Control）なら形式を選択して貼り付けへ振り分ける。設定画面はアプリ全体の設定、現在の表の表示設定は表示メニューから対象の表名を示して開く。

クリップボードはarboardの1つのadapterで読み書きし、HTMLとplain textを1回で登録する。arboardは任意の独自形式を扱えないため、Texcelの内部payload（版、owner ID、同時に書いたplain text、範囲ごとのセル、範囲ごとの左上のコピー元位置）はHTML先頭のコメントにBase64のJSONで埋め込む。内部payloadは、同じプロセスが最後に書いたpayloadの部分とハッシュが一致し、plain textとも一致する場合だけ使う。HTML全体では比べない。macOSはHTMLを読み返すときに独自の見出しを付け足すためである。他のプロセスやアプリが書いた同じ形のコメントは使わず、外部から原文や数式を持ち込ませない。plain textの行区切りはWindowsだけCRLFとし、引用符内のセル内改行はLFのまま書く。読み込みではCRLF・LF・CRを受け付ける。

コピー・切り取りの状態（owner ID、文書、表、範囲、コピー時の文書版、切り取りか）はアプリ全体で1つだけ持ち、点線の表示と切り取りの移動に使う。文書版が変わった時点、Esc、次のコピー、他のアプリのコピーを貼付時に検出した時点で解除する。監視のための継続再描画はしない。切り取りの移動は、この状態のowner IDと貼付時のHTMLが一致し、同じ文書の同じ表・同じ文書版で、optionsが既定の場合だけ要求に含める。移動の要求は通常の貼付と同じworkerの1回の構造変更で準備し、移動先のセル、元範囲のうち移動先に含まれないセルの消去、元範囲を参照する他セルの数式の書き換えを、原文・モデル・計算snapshot・Undoへ同時に確定する。切り取り範囲と貼付範囲の大きさが違えば変更しない。

通常コピーの外向けplain textは画面と同じ表示文字列とする。Markdown記号や式の文字列指定markerをそのまま外向け文字列へ混ぜず、markerを除いた後の修飾も通常の表示解析に従う。Texcel所有の内部payloadは原文と表示上の値・対応修飾を区別して保持する。通常貼付では原文・型・対応修飾を維持し、値のみでは原文の修飾を持ち込まず、式に見える値は永続的な文字列指定を行う。数式の値化では既存の計算結果の版とFresh判定を維持する。セルの右クリックメニューは切り取り・コピー・貼り付け・形式を選択して貼り付けを先頭に並べ、その後に挿入・削除・消去などを続ける。

修飾付き貼付でMarkdown原文を生成した場合、workerで確定する文書モデルの入力もその原文に一致させる。CSV昇格では貼付範囲外の既存セルも新しい原文へ揃える。sourceだけを書き換えて編集欄に旧入力を残さない。原文・モデル・計算snapshot・Undoを1つの変更として確定し、通常貼付に必要なCSV昇格も同じUndoへ含める。GFMで保持できない修飾の境界は既存の往復確認付き変換を使い、文字の値を保持したうえで省略を通知する。

セルの選択中、編集中、IME変換中を区別する。編集は1つの共有バッファで行い、モードを `Input`、`Edit`、`FormulaReference` のいずれかにする。Markdown文書全体のソースdraftは持たない。

既定の編集先はセル内とする。文書表示は `Live` または `Source` の2状態を持ち、文書内の全表に適用する。Liveでは他セルの計算結果とMarkdown修飾を表示し、フォーカスした編集セルだけ既存のraw editorを使う。Sourceでは全セルに原文を表示する。切替は表示だけを変え、共通のセル入力へ即時反映する。

| イベント | 処理 |
| --- | --- |
| F2／ダブルクリック | 元の入力をバッファへコピーし編集開始 |
| 文字入力 | 選択中なら置換編集、編集中ならバッファに入力 |
| IME開始 | 変換中に移行。セル移動のショートカットを停止 |
| IME確定 | バッファを更新。セルはまだ確定しない |
| Enter／Tab | 変換中でなければ編集コマンドを確定し移動 |
| Esc | 変換中は未確定のpreeditを取り消して変換前へ戻る。それ以外はバッファを破棄 |
| 編集バー・セル間のフォーカス移動 | 同じバッファを継続 |
| 見出し・別セルの選択 | 未確定のpreeditを取り消し、通常draftを確定して選択を切り替える。数式の参照選択中は式へ参照を挿入 |
| 表タブ・ウィンドウの切り替え | 未確定のpreeditを取り消し、通常draftを確定してから切り替える |

選択セルから文字を入力またはIMEを開始すると、既存内容を置き換える `Input` で始める。このモードの矢印は編集を確定してセルを移動する。F2で `Edit` に切り替えた後は矢印を文字カーソルへ渡す。数式入力で最初の`=`が入ると `FormulaReference` に移り、矢印で参照先を選ぶ。F2は数式編集中だけ `Edit` と `FormulaReference` を切り替える。IME変換中はEnter・Esc・矢印をIMEへ渡す。

Tab連続入力の開始列は文書・表・次の入力セルに結び付け、通常の文字入力と数式入力の間で保つ。連続中のEnterだけ開始列へ戻り、`Input`中の上下矢印は現在列のまま移動して連続を終える。`FormulaReference`中の矢印は参照先を選ぶ。

セル内と数式バーの切り替えは同じ編集バッファを使う。数式バーの✗は `cancel_edit`、✓は移動なしの確定と同じ処理を通す。`fx`の関数一覧は計算アダプターが評価する関数（`SUPPORTED_FUNCTIONS`）だけを英語名で並べる。IronCalcが知るほかの関数名は、計算しない式を作るだけなので並べない。選んだ関数の呼び出しを挿入した後は `FormulaReference` に移る。一覧は関数名に合わせた幅200のポップアップに右クリックメニューと同じ行の高さで並べ、見えている行だけを描く。待機中と編集中の数式バーはフォント、文字サイズ、余白、縦位置を共有し、名前欄・`fx`・入力文字を縦に揃える。数式バーで編集を始めたときは、クリック位置から復元したキャレットを使う。入力欄の右クリックメニューは編集メニューと同じ遅延テキスト命令（`AppCommand`を`InputOwner::CellEditor`で配送）を使う。eguiは右クリックの押下でキャレットを動かし、フォーカスのない入力欄の選択を畳むので、右クリック時と命令の配送前に編集バッファの選択を入力欄へ戻し、フォーカスも戻す。

IME compositionはDocumentId、TableId、編集session、TextEdit IDで特定したフォーカス中のTexcel editorだけが所有する。F2なしの選択セルからのIME開始も、そのセルの編集sessionを作って最初のPreeditから受け付ける。開始時点のbufferと選択位置を記録し、空のPreeditもsnapshotとして保持する。Esc、IMEのDisabled、ウィンドウまたはeditorのfocus loss、キャレットやフォーカスを移すクリックでは未確定preeditだけを取り消してこの状態へ戻す。通常の文字入力が同じframeでpreeditより前にある場合と、同frameのCommit後に新しいPreeditが始まる場合は、確定済み文字を次の取消snapshotへ反映する。選択セルからIMEを始めたときは、最初のPreeditを受けたraw input処理の中で新しいeditorへフォーカスを移し、描画中に重ねてフォーカスを要求しない。eguiはフォーカス要求のたびにIMEの中断を出力し、winitはその中断で自分のmarked textだけを消す。macOS側の変換は残るため、続くEnterの確定がCommitとして届かず、セルが変換中のまま止まるのを防ぐ。macOSのwinitはIMEが使わなかったキーをpreedit中でもアプリへ渡すため、preedit中のカーソル移動・削除キーはraw inputの段階で捨て、eguiがキャレットを未確定文字の外へ動かして確定文字を重複させないようにする。IME eventの終了通知が欠けても他のkey/click操作を残し、取消後に届いた終端eventを次のeditorへ渡さない。別の文字入力欄のIME中はEnter/Escをdialog操作に使わず、IMEの確定後は通常操作へ戻す。表extentを変える編集がworker処理中なら、見出しやtabの選択変更をworkerの成功後まで保留し、失敗時は元draftと選択を残す。

数式参照入力は既存のセル編集バッファ内の挿入区間を更新し、別の数式バッファを持たない。クリックは1セル、ドラッグは範囲、矢印は参照先の移動とする。F2の文字編集時は矢印を文字カーソルへ渡す。参照の色とグリッドの枠は同じ解析結果を使い、文字列リテラル内のA1等をセル参照として扱わない。参照切替と構造変更は採用IronCalcの構文情報を利用し、独立した式パーサーを追加しない。

選択の矩形と、その中で入力・Enter巡回するアクティブセルを区別する。単一クリックはそのセルをアクティブにし、Shiftによる拡張と矩形ドラッグは選択開始時のアクティブセルを保つ。範囲の終点を入力先と同一視しない。Enter/Shift+Enterは主選択矩形の内部を巡回し、追加の選択範囲も維持する。範囲内の移動で選択範囲そのものを縮めない。ドラッグの選択・自動スクロール・列幅変更は同じ行列の座標対応を使い、固定表示を無視した座標を作らない。大きな表の内容測定はUIで全件走査せず、必要な準備をworkerへ渡す。列幅の自動調整は列の一覧を1つの要求にまとめ、workerは表を一度だけ組み立てて各列を測る。全列の一括調整は表の使用範囲の右端列までを対象とし、結果は表示状態が要求時のままのときだけ全列まとめて適用する。

`SetCells`、`InsertRows`、`DeleteRows`、`MoveRows`、列に対する同等操作、`SetStyles`、`ReplaceSource` を編集コマンドとする。一括操作は複数の変更を1コマンドにまとめる。実装は具体的なenumで十分とし、コマンド用プラグインAPIは設けない。

Undoは変更前後の差分を保持する。保存は履歴を消さず、保存済み状態の印を更新する。表示設定は内容のUndoに混ぜない。巨大操作の履歴は復旧領域の一時ファイルへ退避し、準備できなければ編集前に中止する。

履歴スタックは文書ごとに1つ持ち、表ごとには分割しない。コマンドは対象の表IDと変更範囲を持つ。表の追加・削除も復元可能なコマンドにする。Undo／Redo後は対象表と変更範囲の先頭を可視化する。複数表に及ぶ操作は文書順の最初の対象表を表示し、表示中の表自体が削除された場合は元の位置に最も近い残存表を選ぶ。

未確定の文字編集中は入力欄のUndo／Redoを優先し、文書履歴へ遡らない。セル確定後はその編集を1つの文書コマンドとする。新規コマンドの確定でRedo側を破棄する。文書を閉じると履歴を解放し、復旧情報を永続的なUndo履歴として扱わない。

ウィンドウは文書ID、下部タブは表IDに結び付け、表示名を識別子にしない。1つのウィンドウは1つの文書だけを持つ。開く要求は、正規化したパスと外部identityで既に開いている文書を探し、見つかればそのウィンドウを前面に出して新しい文書を作らない。各表の選択・スクロール位置は `ViewState` に保持する。表はMarkdown文書順で表示する。下部タブの選択自体で順序を変えない。Markdownの見出し由来のタブ名は表示用とし、周辺文章を書き換えない。

CSV由来の文書にMarkdown修飾や2つ目の表を追加する場合、昇格と編集を1つの共通Undo commandとして適用する。CSV sourceをUndo対象とし、最後に実際に保存したpath・file identity・saved revisionはUndoで過去へ戻さない。現在sourceの形式と保存先拡張子の形式が一致するときだけ通常保存先として使い、不一致なら保存先を選ぶ。Save As成功時だけ保存先とidentityを更新する。この判定をウィンドウの未保存印・終了確認・復旧でも共有し、取り込み元のpathがあるだけでMarkdown保存済みとは扱わない。保存先の外部変更は9節の保存時の確認に従う。CSV昇格では先頭行をGFM見出しに使い、空見出し行を追加して座標や式参照をずらさない。見出しの役割が変わることを変換レポートへ示す。

各表はExcelのシートと同じく、1,048,576行×16,384列までの任意のセルへ移動できる。編集の確定前に、変更後の文書を現在の形式で再読み込みできるかを、読み込みと同じ資源上限で判定する。Markdown・CSVではファイル全体が64 MiB、セル数が50万までで、セル数の数え方は各形式の読み込み規則に従う。入力・貼り付け・行列の操作などで上限に達した時点で警告し、上限を超える変更は一括で退けて直前の内容と履歴を保つ。移動やスクロールは文書サイズを増やさない。表extentは保存範囲であり、A1を左上に固定し、空でない原文を持つ最も下の行・最も右の列までの矩形とする。extent外への入力・貼り付けは、構造変更とセル編集をworkerで一括準備し、表extent、Markdown/CSV source、cell input、calculation snapshot、Undo entryを同時に確定する。間の空行・空列は空セルとして含める。セルを空にした結果、extentの右端・下端に空の行・列が残った場合は、Texcelが追加した行・列だけを切り詰める。読み込んだsourceに元からあった行・列は、行・列の削除コマンドでだけ取り除く。raggedな既存行の欠落fieldへの入力は、その行の必要幅だけを補う。失敗時はrootと履歴を変更しない。この規則はMarkdownの各表、CSV、取り込んだ表、追加した表（空のシートから開始）に共通とする。並べ替え、重複、前後空白除去、転置、検索・置換の対象「表」、Ctrl/Cmd＋Endは表extentを対象にする。すべて選択・行全体・列全体の選択はシート全体を選ぶが、コピー・消去・書式は表extentとの重なりだけを扱い、空のセルを列挙しない。貼り付けでは貼り付け内容の大きさだけを扱う。全シート・行全体・列全体の選択へ貼り付ける場合は、選択中のセルを開始位置とする。

Markdownでは1行目を見出しとし、extent内で値のない見出しは空の見出しとして書く。追加した列の区切り行は既存の列と同じ書き方（例：`| --- |`）にそろえる。すべてのセルを空にした新規文書は、空の見出し1行と区切り行だけの表を書く。extentの変化を示す点線・追加記号・成功通知は表示しない。保存範囲を画面で示す場合は、実データの罫線と区別する。

## 5. グリッド描画

行と列の両方向を仮想化する。表extentによらず、ウィンドウを埋める行・列のセルを描画する。スクロールできる範囲は、表extentと現在の表示位置のうち遠い方に1画面分を足した大きさとし、端を越えるスクロール・キー移動・名前ボックスの移動でシートの上限まで広がる。表示位置が表extentへ戻ったら、表extent＋1画面分まで縮める。行番号・列記号の欄は表示中の最大の桁に合わせて広げる。表extent内の行番号・列記号はセルと同じ前景色、extent外は弱い文字色で描く。選択中の見出しは背景色で区別する。extentは描画ごとに疎な行列索引の末尾から求め、表全体を走査しない。空のセルのためにメモリを確保せず、シートの端付近でも先頭付近と同じ応答性を保つ。スクロール位置から可視行列を求め、周囲の少量の余白と固定範囲だけを描画する。セルごとに常設の入力ウィジェットを持たず、編集中の1セルだけに `TextEdit` を配置する。

行高は利用者が手動で変えない。標準行高を基本とし、折り返しやセル内改行のある可視行だけ内容に合わせて高くする（上限4,096px）。表のレイアウトは列幅・固定表示だけを持ち、行高は画面側の測定キャッシュだけが持つ。XLSXの行高・非表示行は、取込報告のために有無だけを記録する。テキストの折り返しは表ごとの「折り返す／折り返さない」の2択とし、既定は「折り返さない」とする。セルごとの折り返し書式は参照しない。折り返し高さは表示中のモードで描く内容から測る。ライブ編集ではリンクの文字だけ、ソース編集では原文全体で測り、ライブ編集で原文の長さを使わない。折り返し高さの測定は可視範囲を中心にキャッシュする。列幅の累積位置と測定した行高の累積位置を使って選択・ヒットテストを行う。選択範囲は矩形の集合とし、巨大範囲をセル一覧へ展開しない。

既定の文字配置は値で決める。6.1節の規則で数値とみなすText、型付きNumber、Freshな数値の式結果は右、それ以外のTextは左とし、明示したMarkdownの列配置を優先する。`00123` のように数値とみなさないTextは、四則演算で数値として使っても左寄せを保つ。列幅や自動行高の上限を超えた内容は表示上の省略記号で示し、モデルや保存値を短くしない。

ライブ編集では、表の見出し行の文字を太字で表示する。見出し行はMarkdownでは常に1行目、CSVでは並べ替えの画面で「先頭行を見出し」を選んだときの1行目とする。ソース編集では原文のまま表示し、太字表示で保存内容を変えない。

矩形の追加選択もViewStateへ保持し、選択範囲間の空白を暗黙に含めない。Ctrl/Cmd＋矢印は、値の連続領域内ならその方向の端へ移動する。領域端から同じ方向へ続けて押すと次の値領域の手前側へ移動し、次の領域がなければシート端へ移動する。空セルからは同じ方向にある次の領域の手前側、またはシート端へ移動する。領域端は疎な行／列索引で求め、UIスレッドで表全体を走査しない。

クリップボードの1セル貼付は有限の選択矩形を埋める。物理選択が1セルなら複数セルの貼付をその位置から展開し、有限の複数セル選択なら貼付行列を選択中の可視行数・列幅へ一致させる。全シート・行全体・列全体の選択では、選択中のセルを開始位置として貼付内容の大きさだけを適用する。可視行不足や寸法不一致では変更しない。離れた複数範囲はコピー時に範囲ごとのブロックとして表し、貼付では単一矩形へ自動変換しない。値のみ貼付は同じ計算入力版に紐付くFresh数式結果だけを型付き値にし、貼付先のセル書式を維持する。Fresh結果がない数式は貼付全体を拒否する。

CSV／Markdownのsource再解析では保存できないセル型・書式・リンク・rich textをDocumentの疎なsession stateで保持し、次のworker操作でも原文sourceと重ねて復元する。これはテキストファイル自体の保存形式を変更しない。保存中は貼付・構造変更・構造Undo／Redoの適用順を待たせ、保存要求時点のsourceと後続編集を混在させない。

文字レイアウトのキャッシュキーは入力版、書式、列幅、表示モード、フォントプリセット、フォント倍率、シートの表示倍率とする。毎フレームのMarkdown解析・再計算・全行走査を禁止する。アイドル中は継続再描画せず、入力、スクロール、結果通知などで再描画を要求する。

egui_extrasには可視行だけを描く機構がある [14] が、両方向の仮想化まで自動的に満たすと仮定しない。主要グリッドは専用の描画・選択処理とし、一般的な設定一覧は標準ウィジェットを使う。

独自描画セルには座標、ヘッダー、表示値、選択・編集状態を支援技術へ公開する。仮想化されているセルへの移動要求は対象を可視化して処理する。IME候補位置は編集中のカーソル位置とDPIに追従させ、フォーカスを毎フレーム取り直さない。日本語を表示できるライセンス適合フォントを同梱する。

キーボードフォーカスは現在のグリッドセルだけが所有する。矢印・Tab・Enter・Escを押したframeと離したframeの双方で、選択中のセル自体がフォーカスを保つ。フィルハンドルはドラッグ操作に使い、キーボードのフォーカス順には加えない。ドラッグ中の枠は、離したときと同じ規則でポインタ位置からframeごとに求めた表示だけの範囲とし、文書の選択範囲とUndo履歴は離して埋めるまで変えない。

### 5.1 表示フォント

アプリ設定に `font_preset: Auto | Default | NotoSansJp` を持ち、既定は `Auto` とする。`Auto` はアプリの表示言語が日本語なら `NotoSansJp`、英語なら `Default` と同じ定義を使い、言語の切替時に再評価する。`Default` と `NotoSansJp` は利用者の明示的な選択として扱い、言語によって変えない。保存済みの設定値はそのまま尊重する。文書単位の上書きやOSフォントの列挙は設けない。

| プリセット | 通常表示 | 原文・コードの等幅表示 |
| --- | --- | --- |
| Default（既定） | egui標準を優先、日本語は同梱のNoto Sans CJK JPへフォールバック | egui標準等幅を優先、日本語はNoto Sans Mono CJK JPへフォールバック |
| NotoSansJp | Noto Sans CJK JPを日本語・英数字ともに最優先 | Noto Sans Mono CJK JPを日本語・英数字ともに最優先 |

Notoの日本語版は日本語とBasic Latinを含む [16]。日本語用フォントを末尾に追加するだけでは英数字が別フォントのままなので、Noto設定では各ファミリーの先頭に置く。eguiの `FontDefinitions` の優先順位と `Context::set_fonts` を使う [15]。不足するグリフだけ、登録済みの代替フォントへ固定順でフォールバックする。`Auto` の言語による選択以外に、OSや文書内容によるプリセットの自動変更はしない。

設定画面のフォント見本は標準・太字・等幅・等幅太字の4種を `Aあ12` で並べるだけとし、長い見本を開く操作は置かない。適用時に文字配置と自動行高のキャッシュを無効化し、可視範囲から再計算する。手動指定の列幅は変更しない。描画と編集で共通のフォント定義・行メトリクスを使い、言語ごとに別々に垂直中央寄せしない。

アプリの表示フォントは取り込み元のフォント名より優先する。太字・斜体などMarkdownで表現できる修飾だけを編集内容に反映し、色やサイズは取り込まない。貼り付けでも同じ規則で色・文字サイズ・背景・罫線・数値表示形式を落とすため、編集中のセルはそれらを持たず、グリッドもセル単位のそれらを描画しない。設定変更だけでは文書を未保存状態にしない。

プリセットは必要な通常・太字と等幅のフォント資源をライセンス表示とともに同梱する [17]。混在による差を減らす設計であり、全グリフ・全DPIでの見た目の一致を保証しない。独自のフォント補正エンジンや利用者向けオフセット調整は追加しない。

### 5.2 外観テーマ

アプリ設定に `theme: System | Light | Dark` を持ち、既定は `System` とする。選択値と実際に描画するテーマを分け、以下の規則で決定する。

| 選択値 | 適用するテーマ |
| --- | --- |
| System | OSがダークを通知した場合はダーク。ライトまたは取得不能ならライト |
| Light | OS設定によらずライト |
| Dark | OS設定によらずダーク |

起動時、設定変更時、ウィンドウ基盤からのOS外観変更通知時に再評価する。定期ポーリングやOS別の独自監視機構は追加しない。変更通知を提供しない環境では起動時に取得できる値を使い、取得自体ができない場合はライトとする。

eguiの外観設定とグリッド用の色定義を同じ適用テーマから決める。色の用途は背景、通常文字、グリッド線、選択、編集、エラーにまとめ、描画箇所ごとに判定を散在させない。切り替え時は再描画し、編集バッファ・選択・スクロール位置は維持する。文字レイアウトに色を含めてキャッシュしている場合は、そのキャッシュも更新する。

背景・文字・グリッド線・選択・編集・エラー色をテーマから決める。文字修飾と列配置はMarkdownの表現だけを扱い、セル色や罫線を編集属性として持たない。テーマは表示だけに適用し、保存データと内容のUndoには含めない。

インラインコードの背景は、現在のセル文字色と反対の明るさを選び、ライト・ダークの双方で文字を読めるようにする。

### 5.3 文字・余白・ダイアログの共通規則

アプリ内の文字は次の役割を1か所で定義し、描画箇所は役割名を使用する。表はUIの文字サイズが14論理ポイントでシートの表示倍率が100%のときのegui論理ポイントである。設定のポイント数を論理ポイントへ換算し（macOSは等倍、Windows・Linuxは96/72倍）、eguiの拡大率（論理ポイント÷14）としてシート以外のすべてに一括して適用する。列幅は半角文字数で持ち、描画では「グリッドの等幅フォントで測った半角1文字の幅×文字数＋左右の余白12」とする。累積位置は、幅を指定した列の文字数の和・列数・幅0の列数をFenwick木で持ち、文字幅が変わっても木を作り直さずに求める。シートは「表示倍率÷eguiの拡大率」をグリッドの寸法・文字・余白に直接掛けて描き、eguiの変換で拡大しない（拡大時に文字がぼやけるため）。列幅・行高の保存値と自動調整の測定は100%の値のまま持ち、描画・ヒットテスト・列幅のドラッグの境界でだけ倍率を掛け外しする。測定済みの行高は倍率ごとに測り直す。OSのネイティブメニューとファイル選択画面の文字はOSの標準を使う。

| 役割 | 大きさ | 太さ | 使用箇所 |
| --- | --- | --- | --- |
| DialogTitle | 18 | 太字 | ダイアログ・設定の主見出し |
| PageTitle | 16 | 太字 | 設定のカテゴリ内見出し |
| SectionTitle | 14 | 太字 | 関連項目のグループ名 |
| Body | 14 | 通常 | 本文、項目名、入力値、ボタン、タブ、行と列の見出し、セル |
| Caption | 12 | 通常 | 補足、読み込みの進捗、フォント見本のラベル |

原文・コードもBodyの大きさを使用し、書体だけ等幅へ変える。セルのMarkdown太字等はBodyに対応する装飾として重ねる。任意のフォントサイズをセルの属性として導入しない。アプリ描画の日本語は12ポイント未満にせず、入力値を節見出しより大きく強調しない。行見出しと列見出しは同じ文字役割を使う。

余白は4ポイントの倍数を基本にする。通常の操作ボタンは高さ32、文字の左右に12、アイコンと文字の間に8を基本とし、同じ行で揃える。独立したグループ間は16、グループ内の項目間は8を基本にする。長い文言は幅の拡張または折返しで収め、文字を小さくして逃げない。数式バーは既定1行・外枠なしとし、名前欄・✗・✓・fx・入力文字の縦中心を揃える。右クリックメニュー、表一覧メニュー、Linuxのウィンドウ内メニューはOS標準のメニューに合わせ、行の高さ24、文字の左右に14、行間なしとする。ウィンドウ内メニューのショートカットは「Ctrl+/」「Ctrl++」のように記号で示す。

数式バーと表タブ列は、必要な文字と操作の高さに余白を一度だけ付ける。入れ子の余白を重ねない。egui領域内の上部は、macOS/Windowsでは数式バーの1行、ウィンドウ内メニューを持つLinuxではメニューと数式バーの2行だけとする。文書タブやツールバーを戻さない。

ドロップダウン（コンボボックス）の一覧は右クリックメニューと同じ行の高さで隙間なく並べる。ダイアログのボタンに合わせた既定の高さ32を一覧の行に使わない。

eguiのスクロール領域は端で止め、端を越えて伸びる表現（ラバーバンド）を使わない。eguiはトラックパッドに指が残っているとみなす間は伸びた余白を保持し、指を離した後もしばらく余白が残ってから一度に戻るためである。慣性スクロールは残す。

アプリ独自のダイアログは共通のModal枠を使い、左寄せの主見出し、本文、固定したボタン行で構成する。ウィンドウ中央に置き、利用可能な幅・高さを超える本文だけスクロールする。ボタンを本文の下へ押し出さない。本文と外枠の間に20、見出しと本文・本文とボタン行の間に16を基本とする。入力が必要な最初の欄へfocusを渡し、閉じたら元の編集対象へ戻す。ファイル選択はOS標準ダイアログを使用する。 共通枠の適用だけで完了としない。設定と同じ基準で、確認・エラー・取り込み・保存・検索など、すべての本文を関連する項目でグループ化し、項目名と入力欄を左揃えの共通列へ整列する。説明は関係する操作の近くに置き、不要な区切り線や空白で埋めない。日英・ライト/ダークで各ダイアログの内容と操作が収まることを確認する。

ダイアログ本文は用途に沿って並べる。確認は対象と判断内容、入力フォームは関連する項目と説明、レポートは要約・一覧・選択項目の詳細を分ける。見出しと本文で同じ説明を繰り返さない。入力エラーは関係する欄の近くに示す。短い確認を不要な設定フォームのように大きくせず、複雑な条件を1行へ詰め込まない。ボタン名は「保存」「再読み込み」など結果を示す動作名を使う。

バックグラウンド処理は回答を求めるダイアログにせず、取消操作だけを状態欄に設ける。処理を受け付けたときに「準備しています」などの進捗の文は出さず、失敗したときだけ理由を通知する。処理中でも別のウィンドウへ切り替えられる。状態欄は、利用者が対処すべき失敗と注意、処理中の取消、2つ以上のセルを選んだときの右端の個数だけを表示する。処理中のために指示を受け付けなかったときは、その理由を注意として示す。利用者の指示による処理の完了通知も表示し、文書名は表示しない。完了通知は、指示をworkerへ渡したときにそのジョブのトークンと文言を文書ごとに記録し、同じトークンの結果が成功して反映されたときだけ表示する。取消・失敗・古い結果では捨て、注意（上限到達など）があればそちらを優先する。通知はメッセージIDで区別し、完了通知のIDは `status-done-` で始める。個数は選択矩形の面積から求め、離れた範囲は合計し、重なりは1回、隠れた行・列は除いて数え、統計は計算しない。注意の通知は一定時間が経つか次の操作で消す。取り込みの書式影響の注意だけは「詳細」を持ち、利用者が閉じるか文書を閉じるまで残す。

既定操作はEnter、取消・閉じるはEscで実行する。ただしIME変換中と変換確定直後は奪わず、複数行入力のEnterをダイアログ確定として扱わない。既定操作の条件が未成立なら実行しない。macOSでは取消を左、既定操作を右端へ、Windows/Linuxでは既定操作、取消の順に右寄せする。ボタンの高さと最小幅を揃え、文字に必要な幅が大きければ拡張する。設定は表示変更を即時反映し、閉じる操作を明示する。

## 6. 数式の解釈と計算

### 6.1 対応契約

数式入力は先頭の `=` を含めて保持する。Markdown・CSVでは先頭の `=` を常に数式として解析し、表ごとの有効化設定を持たない。先頭に1個以上のアポストロフィが続き、その直後が `=` の場合だけ、最初のアポストロフィを永続化するliteral markerとして扱う。`'=A1` は文字列 `=A1`、`''=A1` は文字列 `'=A1` として扱う。`'hello` のアポストロフィは文字列の一部として保持する。markerを外した文字は再解釈しないため、数式 `="!"` 内の `!` はシート参照ではない。文字列扱いをローカル設定だけに保存しない。

数式結果を値へ置換したテキストと、値のみ貼り付けたFresh数式結果にも同じmarkerを付けて保存する。Markdown・CSVの再読込後も、その値を数式へ変えない。

| 分類 | 対応範囲 |
| --- | --- |
| 演算 | `+ - * / ^ %`、比較、`&`、括弧 |
| 参照 | A1形式、範囲、相対・絶対・混合参照 |
| 集計 | SUM、AVERAGE、MIN、MAX、COUNT、COUNTA、COUNTIF、SUMIF |
| 条件 | IF、IFERROR、AND、OR、NOT |
| 数値 | ABS、ROUND、ROUNDUP、ROUNDDOWN |
| 文字列 | LEN、LEFT、RIGHT、MID、TRIM、CONCATENATE、VALUE |
| 日付 | DATE、YEAR、MONTH、DAY |

上表を製品の対応契約とする。ライブラリにある関数を無条件に公開せず、対応関数をアプリの一覧で固定する。日時・乱数によって結果が変わる関数、動的配列、構造化参照、名前定義による参照、他の表・シートまたは外部ブックへの参照は評価対象外とする。非対応式は原文と取り込み時の結果を保持する。

Markdownの表に必要なpipeのエスケープとセルの修飾記法は、保存原文に保持する。計算入力では表のエスケープを解き、非数式セルは修飾を除いた内容を既存の型判定へ渡す。太字などの表示修飾だけで参照先の数値を文字列へ変えない。式の判定は元のセル内容が先頭 `=` である場合に限り、修飾を除いた結果が `=` になっただけでは式にしない。

数値は倍精度浮動小数を基本とし、表示桁数と計算精度を分離する。Markdown・CSVのTextを計算エンジンへ数値として渡すのは、正規の10進表記（任意の先頭 `-`、先頭ゼロのない整数部（`0` 単独は可）、任意の小数部・指数部）で有効数字15桁以内の場合だけとする。並べ替えで数値のキーを指定した場合と、既定の文字配置（5節）も同じ判定を使う。`00123`、`+5`、20桁の識別子はTextとして渡す。桁区切り、日付文字列は自動変換しない。空文字列と空セルの違いを計算エンジンへ伝える。

数値とみなさないTextの扱いはExcelに合わせる。範囲を受け取る集計関数（SUM、AVERAGE、MIN、MAX、COUNT、SUMIF等）は範囲内のTextを無視し、`SUM(A1:A2)` は文字列 `00123` を合計しない。四則演算と比較では、数値に変換できるTextを変換する（`=A1+1` は124）。採用IronCalcの挙動を確認し、差がある場合は実装判断記録へ書く。

### 6.2 結果状態

| 状態 | 表示と利用 |
| --- | --- |
| Fresh | 現在の計算入力版の計算結果。集計・結果出力に使用可能 |
| Pending | 計算中。前の結果を出す場合も更新中の印を付ける |
| Imported | ファイル内の保存結果。検証済みの最新値と扱わない |
| Unsupported | 未対応式。保存結果があれば由来とともに表示 |
| Stale | 変更後に再計算できない結果。最新値の集計に使わない |
| Error | `#DIV/0!`、`#REF!`、循環参照など。原文は保持 |

編集コマンドの確定後に文書版を増やす。計算入力版は値・式・計算設定・参照構造など計算への入力が変わった場合だけ進め、計算用モデルへ変更を渡す。書式・リンクだけの変更とそのUndo／Redoでは計算入力版を保ち、同じ入力版の計算結果を継続して利用する。計算要求・結果・表示と結果出力の妥当性は計算入力版で照合し、保存要求や変換レポートは文書版で照合する。

ワーカーは新しい要求を優先し、同一文書の未開始要求をまとめる。ライブラリ内部を中断できない評価は完了結果を破棄してキャンセルを実現する。キャンセル時にUIが終了を待たないようにする。

参照の更新は数式構文を理解するエンジンに委ね、文字列置換で実装しない。コピーは相対参照を移動し、絶対参照を維持する。貼付ではinternal payloadのコピー元位置から移動量を求め、IronCalcの`extend_to`で参照を移動する。シート外へ出た参照は`#REF!`とする。切り取りの移動では、移動するセルの式は切り取り範囲内への参照だけを`move_cell_value_to_area`で移動し、残るセルの式は切り取り範囲内を指す参照と、全体が範囲内にある範囲参照だけを移動先へ書き換える。後者はIronCalcに公開APIがないため、`vendor/ironcalc_base`へ局所修正（`Model::displace_references_to_area`）を加えて同じ規則を使う。移動先に元からあった値を参照していた式は、Excelと違い`#REF!`にせず移動後の値を参照する。HTML・plain textから貼り付けた式は参照を移動しない。参照を移動する式と、切り取りの移動で書き換えを確かめる表内の式に対応範囲外のものがあれば、貼付全体を行わず理由を表示する。Markdownへ貼り付けた式は入力どおりに書き、`*` などにMarkdownのescapeを付けない。escapeを付けると計算エンジンが読む式が変わるためである。行列挿入・削除では参照を追従させ、削除された参照はエラーとする。未対応式の参照を安全に更新できない構造操作は実行せず理由を表示する。

ソートは安定ソートとし、移動する行の式を相対コピーとして再配置する。他セルからの参照は座標を維持する。この規則をプレビューに示し、Excelの全ソート挙動との同一性は保証しない。

Markdown内の各表とCSVは独立した計算単位で、ヘッダーを含む表示行番号をA1参照に使う。XLSX・ODSを取り込むときは既存の計算エンジンASTで式の参照先シートを確認する。自シート内だけの参照はシート修飾を取り除き、表内のA1参照に変換する。他シート・外部ブック参照は式として持ち込まず、キャッシュ結果があれば値、なければ空に置き換えてセル位置付きの診断を作る。式文字列の正規表現検索でシート参照を判定しない。

## 7. ファイル形式アダプター

### 7.1 CSV

読み込み時はまず形式設定を決める。文字コードはBOM、厳密なUTF-8判定、CP932の推定、利用者指定の順に扱う。BOMがあればその文字コード、BOMがなく厳密なUTF-8として読めればUTF-8とする。UTF-8として読めず、CP932として不正なバイト列なしに読める場合は、CP932を選んだ状態で条件画面とプレビューを示し、利用者の確認を経て開く。確認なしにCP932で確定しない。どちらとしても読めない場合は、推定せずに利用者の選択を求める。開いた後に設定を変えて読み込み直す専用の操作は持たない。同じ起動中に閉じたCSVのパスを記録し、そのパスを再び開くときは推定が明確でも条件画面を表示して、前回の設定を初期値にする。区切り候補は引用符を考慮したレコードの列数から提案し、同点なら選択を求める。

レコードとフィールドの元バイト範囲を記録する。引用符対応の走査を用い、単純な改行・区切り文字分割をしない。csvによる解釈と保持用走査が一致しない入力は修復せず診断を返す。

CSV由来文書はMarkdownのセル編集と計算規則を使うが、Markdown記号に見える値は装飾として再解釈しない。太字・リンク等の明示操作、複数表の追加、またはCSVで表せないMarkdown構造を作る操作は、文書をMarkdown編集文書へ昇格する。昇格はその編集と1つの共通Undoにまとめる。ヘッダーなしCSVの昇格時は先頭行をMarkdown headerとして使い、新しい行を挿入しないため値と式座標は移動しない。表示役割の変化はレポートする。昇格時は全CSV文字列を可逆にMarkdown escapeし、表示値を変えない。既存CSV source、方言、path、外部identityはUndo可能な前後状態として保つ。

通常CSV保存は、未変換の単一表をそのCSVの元方言・raw record情報で出力する。変更しないrecordはbyte rangeからそのまま書き、セル編集では元の引用有無を維持し、区切り・改行・引用符が追加された場合だけ必要な引用を加える。行列を変えたrecordだけを再生成する。UTF-8・BOMなし・LF・末尾改行ありという既定値は新規CSVにだけ適用し、既存CSV保存では元の文字コード・区切り・改行・ragged shapeを引き継ぐ。空recordと存在しない末尾fieldを区別する。

Markdown修飾や追加表のある文書を名前を付けて保存でCSVにする場合は、同じ流れの中で対象TableIdと「式のまま／計算結果」を選び、変換出力を作る。確認時に固定したDocument revision、TableId、Table revisionを出力完了まで照合する。文書全体を表せないこの部分保存のACKは、文書の保存先・CSV backing・saved revision・dirty状態・復旧情報・close要求を更新しない。このことを保存前の確認に明記する。文書全体を表せる単一表CSV保存だけが、通常の保存ACKとして保存先を更新する。

先頭の `=` は数式として扱い、`'=` は保存可能な文字列literal markerとして扱う。markerを含む値と、markerで始まる文字列は原文のエスケープ規則で区別する。文字コード変更時に表現できない文字がある場合は、対象を示して保存を停止する。

### 7.2 Markdown

GFMオプション付きパーサーで表の範囲を取得し、元の文書バイト列へ対応付ける。オフセット取得だけで完全なセル位置が得られると仮定せず、表範囲内の区切りとエスケープを保持用に走査する。コードブロックや参照リンク定義は文書の構文情報を利用する。セルの全体編集は表のMarkdown原文に反映し、文書全体の原文パネルや独立した適用処理は作らない。

セル修飾はeguiの文字レイアウトへ変換する。任意HTMLエンジンは組み込まない。ソフトな改行は通常文字処理、`<br>` は明示改行とする。リンクの表示と実行を分け、外部URLは利用者操作時だけOSへ渡す。

セル単独の変更は対象範囲の差し替え、行操作は対象行の生成、列操作は対象テーブルの再生成とする。複数箇所の差し替えは元オフセットの降順で行う。保存後に位置情報を再生成する。文書全体をASTから再出力しない。

表の外側のパイプ、余白、区切り行の配置指定は未変更なら保持する。CSV値をMarkdown化するときは、bold、italic、strike、inline code、link、改行、pipe、formula markerをescapeし、元のCSV値を表示上で再現する。新しく書く表は外側パイプあり・セル前後1空白・区切り線 `---` とし、列幅を空白で揃えない。既存の表でもTexcelが書くセルの空白は書くときの規則で決め、元のセルの空白を引き継がない。その行がセルを空白で区切っていれば前後に1空白、`|a|b|` のように詰めて書く行なら空白なしとする。空セル `|  |` への入力も、列揃えの空白を持つセルの書き換えも同じ規則に従い、書き換えないセルは元のバイトを保つ。

配置を変更した列と新しい列には、同じ表の区切り行の書き方を用い、配置に応じてコロンを付ける。配置なしの基本形は `---`。変更しなかった列はハイフンの数と空白を保持する。列の移動・複製・削除には配置も追従し、挿入列は配置なしとする。行操作・ソートは列配置を変えない。配置の変更は1回でUndoできる。Markdown表としてコピーするときも選択した列の配置を区切り行へ書く。CSVで配置を指定したときは7.1節の規則でMarkdownへ昇格し、CSVへの保存では配置の損失を確認する。

余剰セルや不足セルは元の個数を保持する。GFMの通常描画と異なる余剰セルは診断付きで表示し、破棄しない。列が0本になる削除は表の削除として扱う。表の削除では、表の直前にある見出し行を、表との間に空行以外の内容がなく、その見出しが表名の元になっている場合に限って一緒に削除し、見出しと表の間の空行もまとめて取り除く。前後の文章との間には空行を1つだけ残す。それ以外の表外の文章は変更しない。表の削除のUndoは見出しも元のバイト列へ戻す。

### 7.3 XLSX・ODS

umya-spreadsheetのreaderで各sheetを読み、セルの原文値・対応する数式・cached resultをMarkdown編集モデルへ変換する。sheetごとに1つのMarkdown表を作り、sheet名を表名へ使う。XLSX文書をそのまま保持したり、XLSXへ保存・出力したりしない。

文字色、背景色、罫線、セル結合、数値書式、入力規則、条件付き書式、その他の未対応構造はMarkdown表へ移さず、対象範囲と扱いを読み込みレポートへ集約する。AutoFilter・入力規則・条件付き書式は内容を解釈せず、範囲ごとに「Markdownでは保持できません」として記録し、表の大きさを広げない。結合は左上に値を残して他の座標を空にする。編集中の文書は結合セルを持たないため、選択・移動・描画・行列操作に結合の扱いはない。1904日付系を使うXLSXは、Markdownへ日付系を引き継がず、日付値や日付関数の解釈が変わり得ることを取り込みレポートで明示する。編集中の文書の日付は常に1900日付系で扱う。保存済み結果のない式を0やFresh結果に変えない。同一sheet内参照はAST/APIで参照先を確かめ、sheet修飾を除いて表内参照へ書き換える。他sheetまたは外部参照はcached resultがあれば文字列値、なければ空へ置き換え、理由とセル位置をレポートへ記録する。

各列について見出しを除く値のあるセルの水平配置を調べる。すべて左・中央・右のいずれかに一致すればその配置を取り込む。「標準」は指定なしとして扱う。配置が混在すれば列は指定なしとし、該当する列と「列の配置を1つにできない」という理由を取り込みレポートに示す。

ODSはzipの `content.xml` と、名前付きスタイル用の `styles.xml` だけを読み、XLSXと同じシートの中間データへ変換した後は7.3節の取り込み・数式・レポートの経路を共用する。`mimetype` が表計算でないもの、`manifest.xml` に暗号化情報があるもの、上限を超える大きさのものは読み込みエラーにする。行・セルの繰り返し（`number-rows-repeated`・`number-columns-repeated`）は内容のあるものだけを展開し、LibreOfficeがシート端まで書く空行・空セルは展開しない。書式だけを持つ空のセルは表の範囲に含めない。値は `office:value-type` に従って数値・真偽・文字列にし、日付・時刻は1900日付系のシリアル値へ変換して表示形式の損失を報告する。段落はセル内改行、`text:s`・`text:tab`・`text:line-break` は空白・タブ・改行とし、`text:span` の太字・斜体・打ち消し線と `text:a` のリンクは修飾として残す。数式（OpenFormula）は文字列リテラルを保ったまま、`[.A1]`・`[$Sheet.A1:.B2]` などの参照をA1形式へ、引数区切りの `;` を `,` へ、配列定数の区切りをExcel形式へ字句単位で書き換え、構文の解釈は計算エンジンに任せる。参照の和・積演算子、別ブック参照、`of:` 以外の名前空間の式は書き換えず、保存済みの値か空にしてセル位置を報告する。コメント、図形、名前付き範囲、入力規則、条件付き書式、フィルターは取り込まず、シートの非表示状態は引き継がず、要素名を報告する。

### 7.4 HTMLテーブル文書

HTMLを入力として表を抽出し、各tableをMarkdown表へ変換する。通常のMarkdown編集、Undo／Redo、MarkdownまたはCSV保存を使う。HTMLの原文範囲保持・cell内HTML編集・HTML保存は行わない。テーブル外の内容、CSS、script、埋込み資源は取り込まず、実行・取得もしない。入れ子や曖昧な表構造、Markdownで表現できない情報は取り込み時のレポートに記録する。文字コードはUTF-8のみを受け入れ、UTF-8 BOMを許可する。他のcharsetを宣言するHTMLは読み込みエラーにする。

本文セルの水平配置も7.3節と同じ列単位の規則で取り込む。値のないセルと見出し行は判定から除き、指定のない本文セルは配置なしとして扱う。

### 7.5 変換レポート

各項目に分類（保持・変換・欠落・処理不能）、影響（内容・書式）、表と範囲、理由を付ける。影響は翻訳文や理由文字列から推測しない。値・数式・表構造への影響は既定とし、読み込み側が書式や印刷設定だけと分かる項目を明示的に書式影響へする。未知の損失は内容影響のままにする。内容影響の項目をレポートの先に並べ、同種の項目は件数でまとめる。読み込み中は診断を蓄積し、項目ごとのモーダルを表示しない。

読み込み成功時にレポートを確定して文書に保持する。内容影響の変換・欠落・処理不能がある場合は、文書を開いた後にモーダルを1回自動表示する。書式影響だけなら状態欄に注意の通知と「詳細」を出し、保持のみなら通知しない。レポートの再表示は、内容影響ならモーダルを閉じるまで、書式影響なら通知の「詳細」から行う。ファイルメニューにレポートの項目は置かない。通知と読み込み成功表示は対象文書IDに結び付け、別文書を選択中は表示しない。ダイアログは要約と詳細、「閉じる」「ファイルに保存」で構成し、確認チェックや保存を必須にしない。レポートは読み込み時点の記録とし、セル編集で書き換えない。

「ファイルに保存」は保存先を選び、UTF-8のテキスト（`.txt`）で出力する。拡張子を含む入力ファイル名、UTC instantとして保持した読み込み日時のOSローカル表示、入力形式、分類別件数、表・範囲・理由を含める。日付と時刻の並びはUI言語ではなくOSの地域設定から取得し、OSのローカルタイムゾーンへ表示時に変換する。OSの書式APIが使えない場合は `YYYY-MM-DD HH:mm TZ` とする。保存のキャンセルや失敗で文書やレポートを破棄せず、失敗時は理由を表示して再試行できる。レポート保存は文書の保存状態に影響しない。自動的なレポートファイル作成や履歴管理は行わない。

読み込みに必要な文字コード等が決定できない場合の入力要求と、読み込みを成立させられないエラーは、この事後レポートとは区別する。読み込み失敗を成功レポートで隠さず、編集文書として確定しない。

読み込みレポートは結果・箇所の一覧と詳細を見出し付きの3列にして固定の高さで並べ、結果列の幅は最も長い分類名に合わせる。対象範囲は詳細の中でスクロールする。CSV保存と計算結果でのMarkdown書き出しの変換レポートは、現在の文書版と保存時の選択から生成し、読み込みレポートの確認を流用しない。項目の表番号・表名は実際の表と一致させ、パスはファイル名を主に示す。処理不能がある場合は出力しない。変換・欠落がある場合は出力前に1つのダイアログで要約し、続行またはキャンセルを選べる。同じダイアログからレポートを任意保存できる。保持のみの場合は追加の確認を求めない。

変換順序は「式または結果の選択 → Markdown修飾 → 値の文字列表現 → CSV field escaping」とする。名前を付けて保存でMarkdownを選び「計算結果」を指定した場合は、各数式セルをFreshな計算結果の文字列で置き換えてGFMへ記録し、それ以外のセル・表外の文章・区切り行は通常のMarkdown保存と同じ規則で保つ。計算結果が `=` で始まる文字列なら、文字列literal markerを付けて式として再解釈されないようにする。この書き出しは文書全体を表現しないため、9節の部分保存と同じく保存先・saved revision・dirty状態・復旧情報を更新しない。「保存」と「式のまま」の名前を付けて保存は、数式を式のまま記録する。CSV出力は値を文字列へ変換し、Markdown修飾・列配置・他表を省く内容は事前レポートへ記録する。

未更新結果を含む「結果のみ」の出力は既定で止める。利用者が保存済み結果の使用を明示した場合だけ、その状態をレポートに残して出力する。CSVの式出力は外部アプリが評価する可能性を出力画面に表示し、勝手に式や文字列を改変しない。

## 8. 検索・並べ替え

検索は原文を既定とする。表示結果の検索は結果状態を含めて表示し、置換する場合は原文との差分を提示する。置換は元文書のスナップショットで対象を確定し、再帰的に置換しない。

フィルター（条件による行の絞り込み表示）は設けない。

CSVはヘッダーなしを既定とし、並べ替えの画面で先頭行を見出しとして除くかを選べる。Markdownと取り込んだXLSX・ODSは表の先頭行を見出しとし、並べ替えから常に除く。この指定は原文・保存dirty状態を変えない。

ソートのキー型は列設定に従う。既定は文字列のUnicode順、数値・日付は明示指定時のみ解釈する。同値なら元の順序を維持する。型不一致・エラーは有効値の後、空白は最後とし、この区分順は降順でも維持する。

ソート時の数式参照は6.2節の規則に従い、移動する式を相対コピーとして再配置し、他セルからの参照座標を維持する。この規則をプレビューに示す。

数式結果を条件に使う操作は同じ計算入力版で確定した最新結果を使う。未対応・未更新セルを含む条件は診断し、古い結果で代用しない。大規模操作の対象と変更差分はワーカーで生成し、成功時だけ適用する。

## 9. 保存・設定・復旧

閉じる確認はウィンドウ（文書）ごと、終了確認は未保存の全文書を1つの一覧で行う。終了時の一覧は読み込みレポートと同じく見出し付きの「文書」「状態」の2列に枠のない行で並べ、変更のない文書は載せない。下書きの処置が必要な文書は、その行の右端に処置のボタンを置く。文書に結び付くダイアログと通知はその文書のウィンドウに、設定と終了の一覧は前面のウィンドウに出す。復元した文書はそれぞれ新しいウィンドウで開く。最後のウィンドウを閉じたとき、macOSはアプリを終了せず、Windows・Linuxは終了する。確認は文書の保存状態と内容変更を分けて判定する。変更していない無題・取り込み文書に保存確認は出さない。文書のdirty状態、未確定の編集buffer、Markdown source draft、未完了の文書変更は確認対象とする。選択肢は「保存して閉じる」「変更を破棄」「キャンセル」、終了時の一覧では「すべて保存して終了」「すべて破棄して終了」「キャンセル」とし、保存成功後に閉じ、破棄はdraftを含めて対象文書だけに適用する。キャンセルまたは保存失敗では編集と文書を保持する。起動時に自動作成したplaceholderウィンドウは、利用者入力や変更がなく、読み込みworkerが成功した場合だけ、そのウィンドウで読み込み文書に置き換える。失敗や編集後の成功ではplaceholderを残す。

最近使ったファイルはアプリ設定へ最大20件を保存する。読込成功または文書全体の名前を付けて保存が成功したパスを先頭へ移し、同じパスを重複させない。取り込み元のXLSX/ODS/HTMLも再度開ける履歴として保持する。取消・失敗した読込、部分CSV出力、レポート保存は成功履歴へ加えない。存在しない履歴を選んだ場合は通常の読込エラーを示し、後続の読込要求を失わない。設定の遅延読込では、この起動中に成功した項目を優先して過去の履歴と統合する。 CLI等の相対パスは受信時の作業ディレクトリに結び付けるが、シンボリックリンクの解決順序を変えるため`..`を実I/O前に除去しない。履歴にも同じ対象を開けるパスを保持する。OSのパスがUTF-8文字列で表せない場合も、履歴の保存によってアプリ設定全体を保存不能にしない。

通常保存と形式変換を分ける。Markdownは元文書全体を通常保存する。未変換のCSVは元のCSV sourceへ通常保存できる。HTML・XLSX・ODSの取り込み文書は元ファイルのpathを保存先として持たず、最初の保存でMarkdown・CSV・TSVの新規保存先を選ぶ。保存形式の拡張子は、CSVは `.csv`、TSVは `.tsv`、Markdownは `.md`・`.markdown` とし、選んだ形式と違う拡張子では保存しない。CSV文書は、選んだ形式が元の区切り文字を保てるとき（TSVはタブ、CSVはタブ以外）だけ元のバイト列へ差分を当て、それ以外は書き出しとして書き直す。保存形式一覧にHTML・XLSX・ODSは含めない。

CSVへの部分保存は、現在のTableId、Document revision、Table revisionを確認時に固定してworkerへ渡す。確認対象から書き出し完了までいずれかが変われば停止し、再確認を求める。複数表・Markdown修飾等を省く部分保存は、名前を付けて保存から行う別ファイルへの書き出しであり、成功してもpath、CSV backing、saved revision、文書全体のdirty状態、recovery情報、close ACKを更新・削除しない。文書全体を表せる新規の単一表CSV保存だけが通常保存としてsourceとpathを切り替える。

CSVからMarkdownへの昇格は共通Undoに含める。Undoは元のCSV source/pathを復元できるが、Document revisionとsaved revisionを巻き戻さない。pathへ戻すときも、9節の保存時の確認を行う。

保存要求時の不変スナップショットを使い、同じディレクトリの一時ファイルへ書き込む。書き込み・フラッシュ成功後、OSの置換操作で保存先を置き換える。置換不能なら元ファイルと編集状態を保持してエラーを返す。置換後の電源断耐性はOS・ファイルシステムに依存する。

読み込み時と保存成功時に、ファイルの内容ハッシュ・サイズ・更新情報を記録する。編集中にファイルを監視・定期確認しない。保存直前にだけ記録と照合し、一致しなければ「上書き」「名前を付けて保存…」「キャンセル」を1回確認する。「上書き」を選んだ場合だけ置き換える。保存先が存在しない（削除・移動された）場合は確認せず、元のフォルダーが存在すれば同じパスへ新規保存として作り直し、なければ名前を付けて保存へ案内する。差分表示、再読み込みの提案、外部変更の状態表示とメニュー項目は設けない。OSのエラー文を翻訳文の代わりに表示しない。確認後の他プロセスによる書き込みまで完全に排除できるとは保証しない。自動マージは行わない。

保存中に編集が進んだ場合、保存完了は要求時の版だけを保存済みとし、最新の編集は未保存のままにする。文書の生存期間内で版を単調増加させ、Undoで内容が戻ることと非同期処理の版識別を混同しない。

設定はOS標準のアプリデータ領域に置く。フォントプリセットなどのアプリ共通設定と、文書に依存する設定を分ける。後者はファイルパスと内容識別情報（サイズとSHA-256）に結び付け、文書ごとの表示モード（ライブ編集／ソース編集）と、表ごとの折り返しと画面レイアウト（列幅・固定表示）だけを保存する。表の設定は表の位置と名前が一致するときに適用し、保存していない行・列の挿入などで構造が変わっている間は座標に依存する設定を再適用しない。内容が外部で変わった場合も再適用しない。表示設定が欠けても開けるようにする。設定ファイルは形式の版番号（現在は1）を持ち、異なる版は読み込まずに通知する。公開前の試作版が書いた形式との互換は持たない。

設定ファイルが存在しない初回起動は既定値で開始し、設定読込エラーを表示しない。最初の保存時に設定ファイルの親directoryを作成する。破損、権限拒否などNotFound以外の読込・保存エラーは利用者へ示す。

アプリ言語は`System | English | Japanese`としてアプリ共通設定へ保存する。`System`はOS言語が日本語なら日本語、それ以外は英語を選ぶ。言語切替は再起動なしで画面と保持中の通知へ反映し、未対応OS言語では英語を使う。設定の遅延読込は利用者が変更した言語を上書きしない。言語変更は文書内容、dirty状態、Undo履歴、数式結果を変更しない。新規文書・表の既定名だけは作成時の言語を使い、既存名は変更しない。レポート保存は要求時の言語を固定して、一つの出力内の言語を揃える。新規文書は空のシートから開始し、保存時に表extentの規則でGFM表を作る。

復旧情報は元ファイルの識別情報、編集差分、未確定バッファを保持する。編集が止まって2秒後、連続編集中は最大30秒間隔を目安に退避する。成功した通常保存の版までは退避情報を整理する。次の起動時は、退避した作業を確認なしにそれぞれ未保存の文書ウィンドウとして開く。元ファイルのパスは保存先として保ち、保存時は前述の照合を行う。元ファイルが無い場合や取り込み文書は、無題と同じく名前を付けて保存へ案内する。復元の一覧ダイアログ、「後で」による保留、ファイルメニューの復元項目は設けない。退避情報を読めない場合は、状態欄の注意で件数を知らせ、読めた作業だけを開く。復元したウィンドウを「変更を破棄」で閉じると、その退避情報を削除する。

## 10. 性能と失敗の扱い

可視範囲の描画コストを表全体の行列数から切り離す。読み込みは段階的に進め、確定した範囲を閲覧可能にする。読み込み完了前は編集を許可しない。XLSX・ODSのブック全体の解析や共有文字列展開が必要な場合も、UIスレッドでは行わない。

ワーカー処理はメモリ使用量と同時実行数を制限する。外部ファイルの展開サイズ・セル数を確認し、過大なZIP展開やメモリ確保の前に診断を返す。これは任意サイズのファイルを扱えるという保証ではない。

キャンセル可能な処理は中間結果を破棄する。保存は最終置換前までキャンセル可能とし、置換成功後は成功として報告する。共有編集状態へ途中まで適用しない。

品質の確認対象は、通常の入力応答、IME確定、表示範囲の移動、原文保持、数式の結果状態、変換時の情報損失、保存失敗時の保持に絞る。数値性能目標を置く場合は対象機器・データ・測定条件と一緒に定義する。文書作成時点で性能測定やライブラリ組み合わせの実証を行ったとは扱わない。

## 11. 依存ライブラリの局所変更

IronCalc 0.9.1とumya-spreadsheet 3.1.1は `vendor/` に固定版のソースを置き、`Cargo.toml` の `[patch.crates-io]` で差し替える。変更は採用ライブラリの公開構造の範囲に限り、独自パーサーや追加エンジンを加えない。各変更の内容は `vendor/*/PATCHES.md` に記す。

Texcel本体のコードはMITライセンスとし、`vendor/` の2ライブラリ、同梱フォント、その他の依存クレートは元のライセンスのままとする。`vendor/` への変更は、変更先ライブラリと同じライセンスで提供する。配布用スクリプトは `texcel-licenses` を実行し、その対象OSのリリースに組み込まれる全クレートのライセンス・通知・パッチの各ファイルと、Texcelの `LICENSE`、Notoフォントのライセンスを `licenses` フォルダへ同梱する。パッケージにライセンスファイルがないクレートには、`Cargo.toml` のライセンス表記と作者を記した注記を作り、MITとApache-2.0の標準文を共通フォルダに置く。対象OSのリリースに組み込まれるクレートがBoost Software License 1.0の標準文を同梱している場合は、その本文（題名から後）も共通フォルダに置き、BSL-1.0だけを示すクレート（Windowsの`clipboard-win`など）をこれで補う。共通フォルダの標準文のどれも選べないのにライセンスファイルがないクレートがあれば、同梱を失敗とする。一覧は [README](../README.md#license) に記す。

| ライブラリ | 変更 | 理由 |
| --- | --- | --- |
| IronCalc | 数値書式の指数部の符号 | `[1, 10)` の値に負の指数を付ける不具合 |
| IronCalc | 削除したシートへの参照を `#REF!` にする | 同名のシートを作り直したときに参照が復活しない |

| umya-spreadsheet | インライン文字列の複数runと空の `<t/>` を保持 | 後のrunが前のrunを上書きし、空文字と空セルを区別できない |
| umya-spreadsheet | ペインの `topLeftCell` と行の `ht` 属性の有無を既定値と区別する | 固定枠の位置と行高の指定有無を正しく読み取り、取込報告に使う |
